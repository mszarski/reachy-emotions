# Reachy Emotions

Talk to a [Reachy Mini](https://github.com/pollen-robotics/reachy_mini) and it listens, hears **what** you say and
**how** you sound, and answers with an expressive move it can physically perform. Everything runs on open-weight
models with licence-clean training data.

- **Listens while you talk.** It leans in, nods at your pauses and perks its antennas when your voice lifts. These
  are rules, not a model, so they react within a frame.
- **Hears your tone.** An audio LLM, fine-tuned here, hears the recording itself. On voices it never trained on it
  reads the feeling right 91% of the time, against 42% for words plus a tone classifier.
- **Reacts fast.** A short reaction starts about 0.5–0.9 s after you stop talking. The full response follows at about
  3–4 s, generated by a small flow-matching model that learned how Reachy Mini moves from Pollen's own clips.
- **Stays reachable.** Every frame is projected through the robot's Stewart-platform IK and servo limits, so the head
  never asks for a pose the robot can't reach.
- **Learns from you.** Thumbs up/down and clips you act out with your own face (the puppeteering page) are collected
  for the next round of training. Your ratings decide, because automatic judges agreed with them only at chance.

It started as a recreation of the text-to-motion system from Binh Pham's
[*The best expressive harness for robots*](https://garden.binhph.am/articles/the-best-expressive-harness-for-robots)
([pham-tuan-binh/reachy-motion-generator](https://github.com/pham-tuan-binh/reachy-motion-generator), Apache-2.0),
rebuilt piece by piece with tests. Typing a prompt (*"sneezing"*, *"a cat stalking prey"*, *"heartbroken"*) still works.

## How it works

```
you speak ──► LISTENER (rules: lean, nod, perk antennas while you talk)
   │ you stop
   ▼
HEARING      Whisper → words · WavLM tone models → feeling, arousal, valence
   ▼
RESPONDER    audio LLM (Qwen2-Audio-7B fine-tune) hears the clip → {"feeling", "recipe", "response", "reading"}
   │            └─ as soon as the feeling is out: a quick reaction move
   ▼
RECIPE       go .3 e=-15 p=-8 z=12 E=6 | osc 1.2 z 5 .5 E=7 | hold 1.2 E=1.5     (typed prompts: an LLM planner writes it)
   ▼
PLAN         8 channels at 4 Hz: ears, pitch, roll, yaw, height, body yaw, energy
   ▼
GENERATOR    21.8M flow-matching transformer → 9-DoF motion at 25 Hz
   ▼
REACH        Stewart-platform IK + servo limits on every frame → a move the robot can play
```

The split is what makes it work with only ~9 minutes of real robot motion. *What* to express is world knowledge, so
it comes from LLMs as a short recipe. *How* Reachy Mini moves is learned from Pollen's clips by a generator that never
sees text. More in [docs/architecture.md](docs/architecture.md).

## Quick start

```bash
pip install -e ".[ik,dev]" && pytest

# text → motion (zero-shot planner on HF Inference Providers; HF_TOKEN needed)
python -m rmr.pipeline --prompt "sneezing" --out runs/one \
    --ckpt hf://mszarski/reachy-motion-generator/generator_v2.pt --render

# the live viewer: talk to it at http://localhost:7860
python -m rmr.server --voice-model mszarski/reachy-voice:student/v8-dpo \
    --ckpt hf://mszarski/reachy-motion-generator/generator_v2.pt
```

The trained weights are in private Hugging Face repos. Running the server, the audio responder, the robot client
and the Space deployment are covered in [docs/running.md](docs/running.md).

## Results

| | result |
|---|---|
| Generator | identifies 91.7% of 12 held-out emotions (reference: 89%) |
| Audio responder v2 (live) | 91.0% on real held-out voices (text pipeline: 42.3%); 68.3% on cloned test lines (57.8%) |
| Physically fitting responses | 88–97% |
| Latency on one L4 | hearing 0.2–0.5 s, reaction 0.5–0.9 s, full motion 3–4 s |
| Listener style | picked from 24 by side-by-side votes |

Negative results are kept too: smaller or transcript-free audio models, 4-bit quantisation, planner grounding,
automatic judges. See [docs/results/](docs/results/).

## Layout

```
rmr/            the package: motion, plan, recipe, reach, generator/, planner/, voice, respond, audio_responder,
                listen, react, mood, idle, feedback, server, robot, renderer/
visualizer/     three.js viewer, talk UI and puppeteering page (no build step)
scripts/        data, training, evaluation and rating tools
deploy/         Hugging Face Space and Jobs
data/teacher/   the reference's teacher dataset (10,872 prompt → recipe rows)
tests/          pytest, including Python ↔ JavaScript parity checks
```

## Caveats

These models read *expressed* emotion, not what someone feels, and they vary across speakers, accents and cultures.
Recordings are processed per request and kept only when you rate an answer and opt in to saving the audio. Not yet
tested on a physical robot: only the 3D viewer and the MuJoCo simulator.
